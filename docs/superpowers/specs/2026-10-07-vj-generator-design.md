## 1. 一句话定义

一个跑在浏览器里的实时 3D 生成器：输入歌手名字，输出**镶满钻石的立体字 logo**，
既能全屏投到演出现场的 LED／投影，也能一键录成**无缝循环视频**。

---

## 2. 目标与非目标

### 目标

1. 改一个名字，3D 字立刻重建，**不刷新页面**。
2. 演出时稳定 60fps，卡帧是不可接受的。
3. 场馆断网也能跑。
4. 导出的一条视频，首尾能无缝拼接、循环播放看不出接缝。
5. 字形层可替换——今天用系统字体，以后换手绘或 AI 生成，其余部分不动。

### 非目标（第一版不做）

AI 生成字形、MIDI 控制器、投影映射与多屏、中文复杂排版（竖排／标点避头尾）、
多名字轮播、移动端适配。

这些不是永远不做，而是被挡在明确的可插拔接口后面。

## 3. 视觉规范：钻石满镶

参考图不是一个"3D 字体效果"，而是**五层叠出来的视觉系统**。分清哪些能程序化生成，
是这个项目的第一步。

| 层 | 内容 | 实现方式 |
|---|---|---|
| 1 | 满钻字面 | 程序化 shader |
| 2 | 镀铬立体边 | 3D 挤出 + 倒角 + 金属材质 |
| 3 | 尖刺阵列 | 程序化，沿字形轮廓批量排布 |
| 4 | 血红龙纹背景 | **外部素材**（见 §10 风险） |
| 5 | 定制字形 | 可插拔字形层（见 §4） |

### 3.1 满钻字面

**核心做法**：不增加任何几何面。在片段着色器里按物体空间 XY 铺一层网格，
每个格子内把法线朝格子中心外侧推，形成一个凸点。凸起之后，
**原有的 PBR 环境反射会自己在每颗"钻"上形成高光**。

关键在于**不规则**。规则网格看起来像纱窗，不像钻石。所以每颗钻必须有独立的：

- 中心偏移（jitter）
- 半径（0.30–0.50 格宽随机）
- 凸起高度（0.70–1.28 倍随机）
- 闪烁相位（各自独立，所以是「一颗颗陆续炸亮」而不是整片一起闪）

实测参数（`samples-02`／`samples-03` 已验证）：

| 参数 | 值 | 说明 |
|---|---|---|
| 密度 | 每字高 **22 颗** | 中文字体笔画相对字高比参考图的涂鸦字细，低于 15 颗笔画上只剩一两颗钻，太粗 |
| 凸起强度 | 0.85 | 法线扰动峰值约 27° |
| 抖动 | 0.55 格 | |
| 钻面占比 | 0.42 格半径 | 留出金属底座的缝隙，密铺会失去立体感 |
| 闪光强度 | 0.95 | 闪光指数 26 次方 —— 短促炸亮，不是缓慢呼吸 |
| 闪光颜色 | `#fff6e8` | 微暖白，纯白会显脏 |

**为什么密度按「每字高几颗」而不是世界尺寸**：按世界尺寸的话，名字越长缩放越小，
钻就越稀。按字高比例才能保证长短名字的观感一致。

### 3.2 镀铬立体边

铬之所以"贵"，100% 来自它反射到的环境，不是来自材质参数。所以环境贴图是**程序化搭的虚拟影棚**，
不是一张 HDR 文件（离线也要能用）：

| 灯板 | 尺寸 | 亮度 RGB | 位置 |
|---|---|---|---|
| 顶部柔光箱 | 24×5 | (6.0, 6.0, 6.4) | (0, 12, 0) |
| 底部反弹光 | 18×5 | (1.5, 1.5, 1.7) | (0, −11, 0) |
| 左红板 | 13×13 | (3.6, 0.10, 0.14) | (−14, 0, 0) |
| 右红板 | 13×13 | (2.9, 0.09, 0.13) | (14, 0, 0) |
| 冷蓝背板 | 14×14 | (0.60, 1.40, 2.60) | (0, 0, −15) |
| 正面补光 | 8×8 | (2.4, 2.4, 2.6) | (0, 2, 15) |
| 左后暖点 | 5×5 | (0.9, 0.15, 0.20) | (−6, 8, 6) |

亮度可以超过 1.0 —— 这正是"亮到发光"的来源。灯板少，铬面反射就是几条平淡的色带；
灯板多且色温不同，才有金属那种忽明忽暗的流动感。

材质参数：

| 部位 | 颜色 | 金属度 | 粗糙度 | 清漆 | 环境强度 |
|---|---|---|---|---|---|
| 字面 | `#f2f6ff` | 0.30 | 0.16 | 1.0 / 粗糙 0.06 | 1.95 |
| 边缘（倒角） | `#ffffff` | 1.0 | 0.07 | 1.0 / 粗糙 0.03 | 2.2 |

**倒角是镀铬边的载体。** 几何上倒角段数不足，那道锐利的白色高光带就是断的、带棱角的。
所以倒角段数取 **6**（可调范围 4–10），不是常见的 3–4。

**倒角尺寸必须小于笔画宽度的一半。** 中文字体细笔画（如宋体横画）在归一化后
可能只有 0.05 单位宽，倒角 0.05 会直接把笔画吃掉。默认 0.022，可调范围 0.002–0.06。

### 3.3 边缘装饰

**边缘长什么、怎么排，本身就是字形设计的一部分**，所以不做成写死的锥体，
而是三轴可切：**7 种形态 × 5 种排布 × 3 种朝向**。

从字形几何顶点反推轮廓（按列取每列的最高点与最低点），在轮廓上批量摆放装饰
（`InstancedMesh`）。

| 形态 | 性格 | 几何做法 |
|---|---|---|
| 尖锥 | 经典荆棘冠 | 10 边锥体 |
| 獠牙 | 猛兽、咬合 | 锥体尖端沿 X 弯钩、Z 向收窄 |
| 碎钻晶簇 | 未切割原石 | 5 棱台，逐实例随机绕轴旋转 |
| 刀刃 | 冷兵器、锋利 | 4 边锥压扁成片，再转 45° |
| 滴落 | hip-hop 珠宝"化开" | `LatheGeometry` 泪滴回转体 |
| 铆钉 | 克制、工业 | 半球，压扁 |
| 长针 | 细密、放射 | 7 边细锥 |

| 排布 | 长度随位置的变化 |
|---|---|
| 扇形弧 | `0.5 + 0.5·sin(πt)` —— 中间最长两端收短 |
| 锯齿 | 长短交替（1.00 / 0.46） |
| 递增 | `0.22 + 0.78t` —— 一头重一头轻 |
| 波浪 | `0.34 + 0.66·|sin(3πt)|` —— 三个波峰 |
| 乱序 | 随机，但由固定种子决定 |

朝向：只在上面 / 只在下面 / 上下都有。另可调基准长度、长短随机、外张倾斜。

**所有几何体统一归一化到「高 1、上下居中」**，这样实例的 `scale.y` 就等于长度，
7 种形态共用同一套摆放代码。

**尖刺与字面共用同一个材质** —— 参考图里那些尖刺本身也是镶钻的。

数量按最终世界宽度算：`根数 = 世界宽度 / 0.15`，钳制在 18–110。

**随机必须可复现**：排布用固定种子的伪随机（`mulberry32`），
同参数永远给同一份排布——否则录两遍视频得到的内容不一样，破坏无缝循环的前提。

### 3.4 背景与氛围

程序化生成，不依赖素材（龙纹素材见 §10）：

- 血红径向渐变 + 110 个随机暗红光团 + 边缘压黑暗角，画布 1024²
- 地面平面（给光一个落点，画面立刻有纵深）
- 620 个加性混合火星粒子缓慢上升
- 辉光后处理：强度 0.55 / 半径 0.75 / 阈值 0.72

### 3.5 运动规范

**所有运动都以「每个循环周期内振荡几次」定义，不写独立的秒数。**
原因见 §6.2：要录出无缝循环，所有振荡必须在同一个周期 `L` 内整数次收尾。
写成自由秒数（比如"周期 18 秒"）放进 8 秒循环里，首尾必然接不上。

表中 `k` = 每个循环 `L` 内的完整振荡次数，实际周期 = `L / k`。

| 动作 | 幅度 | k（次/循环） | L=8s 时的周期 |
|---|---|---|---|
| 绕 Y 轴摆动 | ±0.34 rad | 1 | 8.0s |
| 绕 X 轴微摆 | ±0.065 rad | 2 | 4.0s |
| 上下浮动 | ±0.05 单位 | 3 | 2.7s |
| 呼吸缩放 | ±0.7% | 4 | 2.0s |
| 红灯光强脉动（左） | ±12 | 5 | 1.6s |
| 红灯光强脉动（右） | ±10 | 7 | 1.1s |
| 钻面闪光脉冲 | 强度 0.95 | 11 | 0.73s |

各振荡用不同的 `k` 和初始相位错开，避免整片同频呼吸——那种"整体在脉动"的
廉价感就是这么来的。

**想要更慢的运动，就加长 `L`，不要拉长周期。** `L` 默认 8 秒（4 小节 @ 120 BPM），
可在 4–32 秒之间设置；循环越长运动越舒缓，代价是导出文件更大。

幅度要小。名字是要让人记住的，不是让人晕的。

## 4. 字形层（本项目最关键的一层）

### 4.1 结论：从画布描轮廓

"像不像参考图"几乎全由这一层决定。三条路线评估后选定**从画布描轮廓**：

| 路线 | 语言覆盖 | 字体文件 | 授权风险 | 精度 |
|---|---|---|---|---|
| 打包字体文件 | 需逐语言配 | 几 MB ~ 十几 MB | 有（商用授权） | 真矢量 |
| **描轮廓（选定）** | **任意** | **零** | **无** | IoU ≥ 0.997 |
| 用户上传字体 | 任意 | 用户提供 | 用户自负 | 真矢量 |

描轮廓意味着**系统里装了什么字体就能用什么字体**——中文、英文、日文，
以及用户以后自己装的任何涂鸦字体。零下载、零授权、离线可用。

打包字体与上传字体仍然保留为**质量升级路径**（接口相同），
在需要极致精度（巨幅输出）或用户有商用授权字体时使用。

### 4.2 算法

```
画布渲染文字（系统字体，抗锯齿）
  → 取 alpha 通道
  → 墨迹包围盒裁剪（省掉大部分无用计算）
  → Marching Squares 提取等值线
  → 串联闭合环
  → Douglas-Peucker 简化
  → 嵌套深度分析，判定外轮廓 / 洞
  → 归一化到「墨迹高度 = 1」
  → THREE.Shape[] + holes
```

三个来自实测的关键决策：

1. **交叉点用「边的编号」标识，不用坐标。**
   同一条边被相邻两格共享，编号相同就能精确匹配。用坐标做匹配会因为浮点误差
   导致轮廓断裂——这是最容易埋进去的坑。

2. **不做预模糊。**
   直觉上应该先模糊再描，实测相反：画布自身的抗锯齿已经提供了亚像素信息，
   再模糊只会把中文字形的尖角磨圆。`blur=1` 时汉字 IoU 从 0.999 掉到 0.96 附近。

3. **半像素约定必须对齐。**
   像素中心在 `(x+0.5, y+0.5)`。少加这 0.5 会让整条轮廓系统性偏移半个像素，
   误差约 `0.5 × 周长 / 面积`，细笔画上能吃掉 3% 的 IoU。

### 4.3 接口

```js
// 唯一契约：任何字形来源都产出这个结构
letterform(text, options) -> {
  shapes: THREE.Shape[],     // 已归一化到墨迹高度 = 1，y 轴向上
  metrics: { inkW, inkH }    // 归一化后的墨迹尺寸
}
```

实现（`v1` 提供前两个）：

- `canvasTrace`　— 画布描轮廓，默认，任意系统字体
- `fontOutline`　— 字体文件直读真矢量（typeface.json / opentype.js）
- `svgImport`　　— 以后：手绘或设计师给的 SVG
- `aiGenerated`　— 以后：图像模型生成字形再矢量化

**归一化到墨迹高度 = 1 是硬性约定。** 描出来的坐标是像素单位（几百到几千），
而挤出厚度、倒角、钻面密度都是按物体单位给的（0.0x）。不归一化的话，
0.22 的厚度落在一个 1500 像素宽的字形里等于千分之零点几——看起来就是一张纸，
完全没有厚度，倒角一起消失，钻面密度会被算成每字高几百万颗直接糊成噪点。
（这个 bug 实际发生过，是 v1 必须写进测试的回归项。）

### 4.4 实测验证数据

测试台：`vj-generator-lab/`，8 个用例，把描出的矢量轮廓**重新栅格化**，
与原始掩膜比 IoU（4× 超采样覆盖率，避免度量自身的分辨率误差）：

| 用例 | 轮廓 | 洞 | IoU |
|---|---|---|---|
| `A` | 2 | 1 | 0.9982 |
| `口` | 2 | 1 | 0.9998 |
| `回` | 4 | 2 | 0.9998 |
| `王` | 1 | 0 | 0.9998 |
| `舞` | 8 | 6 | 0.9984 |
| `魔` | 10 | 4 | 0.9979 |
| `ASIAN` | 7 | 2 | 0.9983 |
| `SAKEE` | 6 | 1 | 0.9971 |

全部 ≥ 0.997。`回` 的洞中洞、`舞`／`魔` 的复杂笔画嵌套都正确。
平均 245 个轮廓点／用例（单字用例 30–458 点），挤出三角化成本完全不是瓶颈。

**已知局限**：这是"栅格描矢量"，不是字体真矢量轮廓。正常观看距离与投影演出的
尺寸下看不出差别；印几十米巨幅时理论上能看出极细微偏差——那种场景走 `fontOutline`。

### 4.5 字形变形（让字形"独特"）

换系统字体永远只是换来换去都是那个味儿。真正让字形独特的是**在描出来的轮廓上做几何变形**。
四个参数：

| 参数 | 作用 | 范围（字高=1） | 默认 |
|---|---|---|---|
| 加粗 | 沿法线整环外扩／内缩 | −0.040 ~ +0.080 | 0.015 |
| 尖角延伸 | 只在朝外的凸角沿角平分线外推，角越锐推得越多 | 0 ~ 2 | 0.60 |
| 斜切 | 水平错切，做出意大利体那种倾斜 | −0.40 ~ +0.40 | 0.12 |
| 拱形 | 沿水平方向二次弯曲，让整行呈弧形 | −0.25 ~ +0.30 | 0.06 |
| 圆角 | 把角换成圆弧 | 0 ~ 0.060 | 0.000 |
| 毛边 | 沿法线按固定种子的噪声推顶点，做手凿／风蚀感 | 0 ~ 0.012 | 0.000 |
| 透视 | 上宽下窄的梯形变形 | −0.60 ~ +0.60 | 0.00 |

预设：凶悍 / 锋利 / 圆润 / 石刻 / 干净 / 归零 —— 一次设好七个参数，快速对比气质。

实现要点（全部在 Node 里定量验证过）：

- **必须先归一化绕向**（外轮廓逆时针、洞顺时针）。只有在这个前提下，
  边法线 `(dy, −dx)` 才恒为「背离材质」的方向——外轮廓朝外、洞朝洞内。
  沿它推就是让材质变厚，**同一个公式同时管外轮廓和内洞**，不需要分开写。
- **斜接长度必须钳制**。尖角处 `1/cos(半角)` 趋向无穷，不钳制会炸出去；钳到 2.6。
- **只有凸角长尖刺**：`cross(e1,e2) > 0` 即凸角。洞的凹角天然得到 0，不会往洞里长刺。
- 斜切的行列式为 1，面积守恒——这条写进了测试。

**验证方式**：小量外扩 `d` 时面积增量应约等于 `P·d`（Steiner 公式，`P` 为周长）。
实测 8 个用例的比值为 **0.98–1.01**。法线方向若搞反，这个比值会变成负数，立刻暴露。

**这个模块顺带解决了 §10 里"中文字体笔画过细"的风险** —— 加粗参数可以把
宋体那种极细的横画补到足以承载钻面与倒角。预设：凶悍 / 干净 / 归零。

## 5. 系统架构

### 5.0 技术栈

| 项 | 选型 | 理由 |
|---|---|---|
| 3D 引擎 | Three.js 0.160（ES module + importmap） | 真实 PBR、环境反射、后期辉光是现成能力 |
| 组织方式 | 原生 ES module，无构建步骤 | 演出工具要能直接打开就跑，不要构建链 |
| 后处理 | EffectComposer + UnrealBloomPass + OutputPass | 拿不到时安静降级为直接渲染 |
| 录制 | `canvas.captureStream()` + `MediaRecorder` | 浏览器原生，不需要服务端 |
| 音频 | Web Audio `AnalyserNode` | |
| 描轮廓 | 自研，纯函数，零依赖 | 可在 Node 里跑定量回归 |
| 离线 | Service Worker 缓存 | 场馆断网是常态 |

`three` 与后处理模块从 CDN 取，首次加载后写入缓存。
**渲染主循环不得依赖任何 CDN 的实时可用性** —— 资源加载失败必须有明确降级路径（见 §7）。

### 5.1 分层

```
UI 层        控制面板 · 全屏演出模式
调制层       音频分析 / BPM / 键盘触发 → 参数变化
参数层       ParamStore —— 全部状态的唯一真相源
内容生成层   字形 → 挤出 → 尖刺 → 背景（纯计算，不碰渲染，可单测）
渲染层       Three.js 场景 · 材质与 shader · 渲染循环
输出层       全屏投屏 / 无缝循环录制
```

内容生成层与渲染层严格分离，是为了让"算内容"可单元测试、可回归，
也让字形层能独立替换。

### 5.2 组件

| 组件 | 职责 | 输入 → 输出 |
|---|---|---|
| `letterform` | 可插拔字形来源 | 文字 + 变形参数 → `contours` |
| `stylize` | 轮廓 → 定制字形（加粗/尖角/斜切/拱形） | `contours` + 样式 → `contours` |
| `extrude` | 轮廓 → 3D 几何 | `shapes` → `BufferGeometry` |
| `paveMaterial` | 满钻字面 shader | 密度/凸起/闪光 → `Material` |
| `chromeMaterial` | 镀铬边材质 | 金属色 → `Material` |
| `env` | 程序化环境贴图 | 配色 → `CubeTexture` |
| `spikes` | 沿轮廓排布尖刺 | 几何 + 数量/长度 → `InstancedMesh` |
| `backdrop` | 背景层 | 图片/渐变 → `Mesh` |
| `stage` | 场景、相机、灯光、渲染循环、帧率预算 | 上层全部 → `canvas` |
| `modulation` | 音频分析 → 参数增量 | `audio` → `param deltas` |
| `triggers` | 键盘 → 事件（炸裂/切换/闪光） | `keydown` → `events` |
| `recorder` | 无缝循环录制 | `canvas` → 视频文件 |
| `showMode` | 全屏演出模式 | `canvas` → `fullscreen` |

### 5.3 数据流：重建类 vs 每帧类

**这是能跑满 60fps 的核心设计。**

| 类别 | 参数 | 处理方式 | 频率 |
|---|---|---|---|
| 重建类 | 名字、字形、挤出厚度、倒角 | 重建文字几何 + 尖刺 | 仅在用户改动时 |
| 部分重建类 | 尖刺长度／数量、背景图 | 复用文字几何，只重建尖刺或只换贴图 | 仅在用户改动时 |
| 每帧类 | 旋转、呼吸、闪光、音频反应、配色、辉光 | 只改 shader uniform | 每帧，几乎免费 |

拖动任何重建类滑块都必须用 `requestAnimationFrame` 合并，
避免一帧内重建多次。尖刺长度属于部分重建类——只重建尖刺、复用已有文字几何，
否则拖动时会卡。

### 5.4 离线可用

演出场馆断网是常态，工具在台上死掉不可接受。

- 首次联网打开时用 Service Worker 缓存：three.js、描轮廓模块、字体（若有）、背景素材
- 启动自检：缓存不完整时明确提示"请先联网打开一次"，而不是等到台上才发现
- 程序化环境贴图、背景、地面全部不依赖外部文件

### 5.5 UI 信息架构

**这一版是照着同类产品（正念Studio 的「3D VJ 生成器」）重新设计的。** 它比我们
之前的深色单列面板更直观，原因不在配色，而在三条信息架构：

1. **预览与控制分离**：左边一大块 16:9 预览，右边独立侧栏。
   之前把十几个滑块和预览挤在一起，视线要在两处来回跳。
2. **控制分 Tab**：文本 / 外观 / 背景。一次最多看到七八个控件，
   而不是二十个。想调什么先想"它属于哪一类"，这本身就是索引。
3. **用使用者的话，不用实现的话**：
   "边缘高光"而不是"倒角"、"表面粗糙"而不是"粗糙度"、
   "尖角（变凶）"而不是"凸角沿角平分线外推"。

另外两条：

- **视频参数和导出按钮放在一起**（时长 / 帧率 / 码率 / 导出），
  因为它们是同一件事的四个部分，不该分居两处。
- **高级参数收进折叠区**（字形的七个微调参数）。常用的是"气质预设"，
  七个滑块是给要精调的人准备的。

配色：浅色 UI 包深色画布。预览是发光的暗场画面，浅色外壳能把它衬出来，
也让工具更像"产品"而不是"控制台"。

## 6. 输出

### 6.1 全屏演出模式

隐藏 UI，纯画面输出，适配投影分辨率。支持打开独立的输出窗口投到第二块屏。

### 6.2 无缝循环录制

`canvas.captureStream()` + `MediaRecorder`。

**真正的难点不是录制，是让动画本身可循环。** 循环周期 `L` 默认按 4 小节、
120 BPM 换算 = 8 秒。要让录出来的一条视频首尾无缝：

1. **所有振荡都写成 `sin(2πk·t/L + φ)`，`k` 为整数**（见 §3.5）。
   随手写的 `sin(t × 2.2)` 周期是 2.86 秒，放进 8 秒循环里首尾接不上。
2. **粒子系统不能积分，必须按 `(t mod L)` 确定性重算。**
   现在火星用的是"飞出屏幕就随机重生"，那是随机的，录两遍都不一样。
   要改成 `位置 = f(种子, (t mod L))`。
3. **录制时长精确对齐一个 `L`**，不做帧数四舍五入；录完自动比对首尾帧差异。

录制完成后自动校验：首尾帧差异低于阈值才算通过。

### 6.3 音频反应

`AnalyserNode` 取低频／中频／高频，映射到参数：

- 低频 → 闪光强度、尖刺伸缩、辉光
- 中频 → 旋转速度微扰
- 高频 → 钻面闪烁密度

现场用麦克风或线路输入。导出视频时改用音频文件离线驱动，保证同一条音频
每次渲染结果一致。

## 7. 错误处理

演出工具的底线是**不能在台上白屏**。

| 场景 | 处理 |
|---|---|
| 字体渲染不出轮廓 | 回退系统粗体，面板明确提示 |
| 背景图加载失败 | 回退程序化渐变 |
| WebGL 上下文丢失 | **自动重建**（长时间演出必然发生） |
| 离线缓存不完整 | 启动自检 + 明确提示 |
| 音频设备无权限 | 降级为手动 BPM / 节拍器 |
| 描轮廓失败 | 保留上一帧画面，报错不中断渲染循环 |
| 模块加载失败 | 全屏错误页说明是哪一步断的（不是黑屏） |

## 8. 测试策略

| 层 | 方式 |
|---|---|
| 描轮廓 | **定量**：矢量重栅格化 vs 原掩膜，IoU ≥ 0.99（现有 8 用例，扩到 30+） |
| 归一化约定 | 回归测试：几何包围盒高度必须 ≈ 1.0（防"变 2D"那个 bug 复发） |
| 挤出／倒角 | 断言倒角尺寸 < 笔画宽度的一半 |
| 尖刺排布 | 单元测试：给定几何，尖刺数量与轮廓列数一致 |
| 参数映射 | 单元测试：音频 → 参数曲线单调、有界 |
| shader | 固定参数渲染截图对比（视觉回归），防止改一处、钻面变样 |
| 性能 | 帧率预算断言 + 本地性能面板基线 |
| 无缝循环 | 导出后自动比对首尾帧差异 |

## 9. 第一版范围

### 必须做

- 名字输入（中文 + 英文）→ 描轮廓 → 3D 挤出 + 倒角
- 满钻字面 shader + 镀铬边
- 尖刺阵列（顶部扇形 + 底部锯齿）
- 缓慢转动 + 呼吸 + 钻面闪光
- 音频反应（低频驱动闪光与尖刺伸缩）
- 实时预览 + 全屏演出模式
- 录制一条无缝循环视频
- 内置 4 套背景配色 + 支持上传自己的图
- 离线缓存

### 不做

AI 生成字形、MIDI、投影映射、中文复杂排版、多名字轮播、移动端。
其余 5 种效果（液态铬／黄金／熔岩裂铁／冰晶／霓虹裂光）保留为预设，
但不作为第一版的验收标准。
